## 指标语义备忘（读代码核实）

- `Metrics/base_velocity/error_vel_xy`：**平均绝对速度误差（m/s）**，非相对误差。~0.20 m/s 对 ~1 m/s 指令 ≈ 20% 相对，离路线图"误差<10%"的验收还差一截，需 per-terrain 分解再判定。
- `Episode_Reward/feet_air_time` **为负是正常的**：`(last_air_time - 0.5s) * first_contact`，步频快于 0.5s 滞空即扣分。-0.04 属轻度惩罚，不是 bug。
- `Curriculum/terrain_levels` 返回**所有 env 地形行号均值**。初始 ~3.5 后降到 1.4–2.5 = 升级条件（位移 > 地形边长一半 4m）在难地形上多数 env 不满足，质量集中在低难度行。均值本身不是"进度条"，验收要靠 per-terrain 评估。
- `lin_vel_cmd_levels` 返回当前 `ranges.lin_vel_x[1]`。**resume 会重置指令课程**（env 按 cfg 重新实例化，从 0.5 重爬，resume 里 ~128 iter 内已回 0.8，会自行涨回）。

## 评估工具：eval_terrain.py

`unitree_rl_lab/scripts/rsl_rl/eval_terrain.py`：按 (子地形类型, 难度行) 分解摔倒率、绝对/相对跟踪误差、回合时长。要点：用 train cfg 建全地形网格 → 删 `terrain_levels`/`lin_vel_cmd_levels` 课程项冻结 env 分布（generator.curriculum 保持 True，行仍线性映射难度）→ `max_init_terrain_level=9` 覆盖全部行 → 指令范围用 `limit_ranges` → 默认关 `push_robot`（`--keep_push` 可保留）。终止原因经 hook `termination_manager.compute` 快照 `_term_dones` 归因到具体 term。列→地形名映射与生成器 curriculum 分支的 cumsum 逻辑一致（已数值验证：0-1 flat, 2-5 rough, 6-9 slope, 10-13 slope_inv, 14-16 stairs, 17-19 stairs_inv）。

```bash
conda activate env_isaaclab && cd unitree_rl_lab
python scripts/rsl_rl/eval_terrain.py --task Unitree-Go2-Velocity \
    --headless --num_envs 1024 --eval_seconds 300 \
    --load_run <run目录名> --checkpoints "model_*.pt" [--min_iter 9000]
# 输出 <run_dir>/eval/eval_rows.csv（逐回合）+ eval_summary.csv（聚合）
# （unitree_rl_lab.sh -p 写死 play.py，不支持自定义脚本，故直接用 python 调）
# num_envs 建议 ≥1024：地形网格 10行×20列=200 格，256 envs → 每格仅 ~1.3 env 样本太薄；
# eval 纯前向无梯度，1024 envs 的显存远低于训练时的 2048（5060-8GB 可承受）。
```

**行号→台阶高度映射**（验收解读关键）：generator 里 `difficulty=(row+U(0,1))/10`，台阶 `step_height=0.05+difficulty×0.15` → **level r → 台阶高 ≈ 5+1.5r cm**（row0≈5.75、row3≈10.25、**row6≈14.75–15.5cm**、row9≈19.25cm）。**路线图"15cm 台阶能上" = stairs/stairs_inv 地形 level≥6 行**的 fall_rate / rel_err 判读点。eval CSV 里 `difficulty` 列已按 `(level+0.5)/10` 如实记录（勿用旧的 level/9 口径）。

**判读工具 `scripts/rsl_rl/analyze_eval.py`**（2026-10-17 新增，纯 stdlib/CPU，随时可跑）：读 eval_summary.csv → 每 ckpt 打 terrain×level 的 fall_rate / mean_rel_err 矩阵、连续"台阶上限"（从 L0 起第一个不达标行即断；level r → 台阶高 [5+1.5r, 6.5+1.5r) cm）、15cm 门（stairs/stairs_inv 全部 level≥6 格 fall≤0.10 且 rel≤0.15 → PASS/FAIL/INCONCLUSIVE）。`eps < --min_eps`（默认5）的格子标 `*` 且不算通过。已用合成 CSV 验证三态输出。

```bash
python3 scripts/rsl_rl/analyze_eval.py <run_dir>/eval/eval_summary.csv \
    --step_terrains pyramid_stairs,pyramid_stairs_inv   # 名字以 eval 打印的 col->name 为准
```

注意：**尚未在 GPU 上实测**（写脚本时 GPU 被 A2 训练占用，宿主 RAM 仅 ~6GB 余量，不宜开第二个 Isaac 实例）。API 已逐项对照源码核实：`_term_dones` 只记 done env（done 行当步必被重写，无陈旧标志；同步多 term 时取最后一个）、`vecenv_wrapper.step` 返回 `(TensorDict,rew,dones,extras)` 且 `extras["time_outs"]` 在 `is_finite_horizon=False`（默认）时注入、Event/CurriculumManager 对 `None` term 跳过（event_manager.py:341 / curriculum_manager.py:188）、列→地形名映射与生成器 curriculum 分支公式逐字符一致、go2 终止项名为 `time_out`/`base_contact`/`bad_orientation`（time_out 恰为首项，与 fall 归因不冲突）。训练完成后首跑若报错先修运行时细节（如 PhysX 侧行为），API 层预期无碍。
