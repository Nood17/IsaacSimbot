## 0. 先定方向：你要训的是哪一类任务

复杂地形四足训练按"感知方式"分两条路线，难度和成本差异很大：

| 路线 | 观测 | 代表工作 | 难度 |
|---|---|---|---|
| **盲走（Blind / proprioceptive）** | 只有本体感知（IMU、关节编码器、历史） | ETH legged_gym、DreamWaQ、RMA | ★★☆ 起步首选 |
| **感知走（Perceptive）** | 本体感知 + 高度图/深度图 | Extreme Parkour、IsaacLab-Quadruped-Tasks vision | ★★★★ 需要 height scanner + 蒸馏 |
| **分层（HRL）** | 高层规划 + 低层运动策略 | Anymal_Navigation | ★★★ 先训低层再加规划层 |

**建议路径**：盲走 rough → 盲走 stairs → 上 height scanner → （可选）parkour/跳跃。这正好也是绝大多数项目的历史演化顺序。

## 1. 训练方法：针对"复杂地形"场景的核心技术栈

### 1.1 主干算法与框架

事实标准组合是 **PPO（rsl_rl）+ 大规模并行仿真**：

- `rsl_rl` PPO 是 ETH RSL 系（legged_gym / Isaac Lab / unitree_rl_lab）的默认算法，4096 envs、24-step rollout、clip 0.2、GAE λ=0.95、γ=0.99 是常见起点
- Rudin et al. 2022（"Learning to Walk in Minutes Using Massively Parallel Reinforcement Learning"）证明 4096+ 并行环境能把四足行走训练压到几分钟到几十分钟——你机器上 Go2 28k steps/s 就是这个范式
- Isaac Lab manager-based velocity task 是官方模板：`isaaclab_tasks/manager_based/locomotion/velocity/velocity_env_cfg.py` 里 ROUGH_TERRAINS_CFG + height_scanner(RayCaster, 1.6×1.0m, 0.1m 分辨率) + contact_forces(track_air_time) 是复杂地形的标准配置

### 1.2 特权学习与知识蒸馏（感知路线的关键）

- **Asymmetric Actor-Critic**：critic 看特权信息（真实地形、外力、本体真值），actor 只看部署时可得的观测。DreamWaQ (Nahrendra et al. 2023, arXiv:2301.10602) 用 CENet 从历史本体感知中"想象"地形，实现纯本体感知的野外长距离行走
- **Teacher-Student**：Lee et al. 2020 (Science Robotics, "Learning quadrupedal locomotion over challenging terrain") 的 belief-state encoder/decoder——teacher 在仿真里用特权信息训练，student 只用部署可得观测模仿 teacher
- **RMA**（Kumar et al. 2021, Rapid Motor Adaptation）：两阶段——先训带环境因子 z_t 的 base policy，再训 adaptation module 从 state-action 历史预测 ẑ_t，部署时 10Hz 适配
- **ROA**（Regularized Online Adaptation）：Extreme Parkour 用的在线适配方案，JustinMLu/go2-parkour 有 Go2 版复现

### 1.3 课程学习（Curriculum）——复杂地形的成败手

legged_gym 系的经典设计（被所有后续工作沿用）：

- **地形网格**：rows=难度等级（10 级）、cols=地形类型（smooth slope/rough slope/stairs up/stairs down/discrete），比例如 `[0.1, 0.1, 0.35, 0.25, 0.2]`（IsaacGymEnvs AnymalTerrain.yaml）
- **晋级规则**：reset 时若本回合行走距离 > env_length/2 → 升级；< 0.5×commanded distance → 降级（逐 env 独立）
- **指令课程**：按跟踪表现逐步扩大速度指令范围
- **自动课程**（进阶）：LP-ACRL (arXiv:2601.17428, 2026) 用学习进度估计自动调度任务采样分布，ANYmal D 在楼梯/斜坡/碎石/低摩擦面都能维持 2.5 m/s——适合"难度不可排序"的宽任务空间

### 1.4 域随机化（DR）——但要有节制

- 常用项：质量/质心偏移、摩擦系数、外力冲击（push）、观测噪声、执行器强度、关节 PD 增益
- **重要反例**：arXiv:2011.02404（Dynamics Randomization Revisited）实验证明盲目大范围随机化会产生保守策略且不一定提升鲁棒性——**只对真正影响 sim-to-real 的参数随机化**
- 观测噪声比动力学噪声更常被低估：IMU 偏置、编码器噪声、延迟

### 1.5 分层与组合

- 低层 locomotion policy 收敛后冻结，训高层导航策略（Anymal_Navigation 用预训练 rough 策略 + 高层 PPO 避障）
- Walk These Ways (Margolis et al.) 引入步态参数条件化（步频、抬脚高度、本体姿态），一个策略覆盖多种步态

## 3. 技巧与坑（实战清单）

### 3.1 奖励设计

- **任务项**（正奖励）：`track_lin_vel_xy_exp`（指数核 std=0.25 是惯例）、`track_ang_vel_z`、`feet_air_time`
- **正则项**（负奖励，防炸）：`dof_torques_l2`、`dof_acc_l2`、`action_rate_l2`、`lin_vel_z_l2`、`ang_vel_xy`、`flat_orientation`、`feet_slide`、`stand_still`、碰撞（knee/body contact）
- **终止惩罚**：`-100` 级的大额（Digit 配置参考值）
- **坑**：奖励黑客（reward hacking）是常态——只奖"前进距离"狗会原地蹲跳刷分；只奖高度会立定不动。**每个正则项都要有，别图省事删**
- 奖励权重不平衡是最常见 bug：先把跟踪项调对，再加正则项逐项增大

### 3.2 环境与 MDP 设计（He et al. 2020 的教训）

- **初始状态分布 p0(s)**：太窄→学到脆弱策略不泛化；太宽→样本效率崩。合理范围：基座位姿小扰动 + 关节零位附近随机
- **终止条件/infinite bootstrap**：摔倒终止太早会让策略过度保守；但超时 reset 的 value 处理要正确（rsl_rl 已处理 time-out bootstrap）
- **控制频率**：50Hz 策略 + decimation 是惯例；action repeat 影响巨大且常被忽视
- **力矩上限别放开**：放开 torque limit 会得到物理上无法部署的"超人"策略

### 3.3 训练过程中的坑

- **课程卡住**：地形晋级率停滞→检查晋级阈值 vs 实际能走的距离；前期 `max_init_terrain_level` 压低（Isaac Lab 设 5/10 级）让出生点不至于全在最难地形
- **episode 长度**：过短学不到稳态步态；长 episode（20s+）配 termination 更稳
- **knee contact 惩罚**：不罚的话学会用膝盖磕台阶边缘，真机会坏
- **feet clearance/抬脚高度**：复杂地形必须奖，否则拖脚绊倒
- **观测噪声记得加在训练里**：尤其是要上真机或 sim-to-sim 验证时
- **多种子评估**：单次训练曲线骗人；3 seed 起步再下结论（zero2robot 那篇 DR 实验章节的教训：单数字会撒谎）
- **NaN/爆炸**：PPO 的 value loss 爆炸通常先查观测里有没有 inf/nan（height scanner 对空洞地形会返回极端值）

### 3.4 感知路线的额外坑

- height scanner 的 RayCaster 是性能大头：4096 envs × grid ray cast 会让 steps/s 掉 30-50%，可先减分辨率/每 N 步扫一次
- scan 观测 vs 特权编码的组合对性能影响很大——extreme-quadruped-parkour 的消融结论是 actor 直接吃 raw scan 不差，但 critic 需要 priv；scan encoder 预训练或端到端均可
- 相机/雷达噪声模型不做，sim2real 必炸

### 3.5 Sim 侧

- PhysX GPU：确认 `use_gpu_pipeline`（你已验证 PhysX 上 GPU）
- trimesh 地形比 heightfield 更吃碰撞检测性能，但台阶/悬挑只能 trimesh
- 楼梯要注意 `slope_threshold` 和碰撞边界的实际尺寸与 robot 尺寸匹配（Go2 腿短，楼梯 >20cm 就是越障不是上楼梯了）

## 4. 训练策略：从易到难的可执行路线

结合你的环境（unitree_rl_lab + Isaac Lab 已通），建议分四级：

### Level 1：平地速度跟踪加固（已做，巩固项）
- 现成 `Unitree-Go2-Velocity`，确认收敛指标：lin_vel_xy 跟踪误差 <10%、episode length 接近上限
- 跑通就能读懂 reward/events/curriculum 三个 manager 的配置

### Level 2：盲走 rough terrain（本周可开始）
- 打开 `go2/velocity_env_cfg.py` 中注释掉的 `random_rough`/`hf_pyramid_slope` 子地形（保留 flat 10%）
- 2048-4096 envs，先训盲走；关键改动：加 `feet_air_time`、接触惩罚、地形课程
- 验收：rough 上能跟踪指令、摔倒率 <5%

### Level 3：楼梯/离散地形（核心难点）
- 启用 `pyramid_stairs` + `boxes`，这时候盲走大概率不够——需要 height scanner 观测或历史堆叠（proprio history 30-60 帧）
- 两条路二选一先走通：
  a) **盲走+历史**：不改观测结构，靠 GRU/history 隐式感知（DreamWaQ/RMA 路线），成本低
  b) **显式感知**：开 height_scanner，actor 吃 scan 或 scan encoding
- 验收：15cm 台阶能上、20cm 台阶尝试

### Level 4：极端地形/比赛向（可选进阶）
- 沟壑/跳跃：参考 extreme-parkour 系仓库的 terrain generator
- 分层策略：低层走 + 高层避障（Anymal_Navigation 模式）
- 自动课程：LP-ACRL 思想，按学习进度调地形采样分布

### 通用工程纪律
- 每级单独 experiment name + checkpoint 目录；保留上级 ckpt 作为下级的 warm start（初始化权重比从头训快 3-5 倍且更稳）
- 评估指标统一：成功率、行走距离、跟踪 RMSE、摔倒率、单地形 per-level 分布——不要只看 mean reward
- 想发结果时：3 seeds、统一 env seed 评估集、报告 per-terrain 分解而非聚合
